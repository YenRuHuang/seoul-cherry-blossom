# 韓國花季地圖 — 濟州島＋釜山擴充 Design

日期：2026-07-14
狀態：待 user 審查
前身：首爾賞櫻地圖 2026（cherry.mursfoto.com）

## 目標

把「首爾賞櫻地圖 2026」（單城市、單季節）擴充為「韓國花季地圖」（三區域、全年花季），
解決兩個問題：(1) 花季過後網站整年沒有可用內容；(2) 台灣旅客的賞花目的地不只首爾。

## 範圍

### 品牌

- 標題：**韓國花季地圖**，副標「首爾・濟州・釜山 全年花季」
- `<title>`、OG title/description、SEO meta description 連動改寫
- og-image.png 重做（沿用 editorial 視覺風格，換標題文字與三區域意象）
- 花期年份不再放在站名，只放在各景點資料內（如「2026 櫻花祭 4/3～4/11」類註記逐步淘汰，改寫典型區間）

### 資料層（data.js）

所有景點（現有 76 筆 + 新增）統一 schema：

| 欄位 | 說明 |
| --- | --- |
| `id` | **新增**，唯一 slug（如 `seoul-yeouido`、`jeju-noksanro`），取代 `nameKr` 作為全站唯一 identity |
| `region` | **新增**，`"seoul"` / `"jeju"` / `"busan"` |
| `subway` / `subwayKr` | 語意放寬為「交通」：首爾/釜山填地鐵站；濟州填公車路線或「建議自駕」；鎮海填從釜山出發方式 |
| 其餘欄位 | name / nameKr / district / flowers[] / bloom / length / type / lat / lng 不變 |

**前置修復（本功能的必要前提）**：收藏（`toggleFave`/`isFaved`）與 marker 索引
（`spotMarkers`）目前以 `nameKr` 當 key，已驗證存在三筆「안양천 제방」撞名導致
收藏連動錯亂、popup 彈錯位置的 bug。全部改用 `id`。localStorage 舊收藏資料
（存 nameKr）做一次性 migration：讀到舊值時按 nameKr 對回第一筆命中的 id。

**新增景點**（花期寫典型區間，不綁年份）：

- 濟州島 20–28 筆：
  - 春：櫻花（典農路、濟州大學櫻花路、鹿山路）、油菜花（山房山、鹿山路、涯月）、迎春花
  - 夏：繡球花（6–7 月，安德面、終達里）
  - 秋：蕎麥花、芒草／粉黛亂子草（9–11 月）
  - 冬：山茶花／冬柏（12–2 月，Camellia Hill、為美里）
- 釜山 15–20 筆：
  - 春：溫泉川櫻花路、南川洞櫻花街、三樂江邊公園、迎月嶺、大渚生態公園油菜花
  - 秋：勝鶴山芒草
  - 冬：冬柏島山茶花
  - 近郊：鎮海（余佐川、慶和站，行政屬昌原；交通欄註明從釜山出發方式）2–3 筆

資料來源：Visit Jeju / Visit Busan / 韓國觀光公社官方頁面，輔以遊記交叉比對；
每筆座標須在地圖上肉眼核對落點（L3 視覺驗證）。

### UI（index.html / app.js / style.css）

- 篩選列上方新增區域頁籤：`[首爾] [濟州島] [釜山]`
  - 切換時 `map.flyTo` 對應中心：首爾 [37.5665, 126.9780] z11、濟州 [33.38, 126.55] z10、釜山 [35.16, 129.06] z11（鎮海含在釜山視野西緣）
  - 景點列表、花種篩選 counts、搜尋範圍都只算當前區域
  - 預設區域：首爾（現有 URL 分享行為不變）
- 花種篩選列由資料自動長出新花種（繡球花、山茶花、蕎麥花、芒草）
- 收藏跨區域共通，「收藏」篩選只顯示當前區域的收藏

## 不在範圍（YAGNI）

- 不加其他城市（大邱、慶州等）
- 不做月份／季節篩選器（花種篩選已隱含季節）
- 不動 CDN SRI/fallback 與 `localStorage.setItem` try/catch 兩個既有 Medium finding（另開小修）
- 不做多語言、不做後端

## 錯誤處理

- 舊收藏 migration 失敗（parse 錯誤／對不到 id）時靜默丟棄該筆，不阻斷其他收藏
- 區域切換不涉及網路請求，無新增失敗模式

## 驗證
